HOSTEL / PG FINDER - MAANG STYLE PROJECT ROADMAP

PROJECT GOAL
-------------
Build a scalable Hostel/PG Finder platform where students can search,
filter, compare, and review hostels/PGs, while owners can create and
manage listings.

TECH STACK
----------
Frontend:
- React.js
- Tailwind CSS

Backend:
- Node.js
- Express.js
- MongoDB
- Mongoose

Additional:
- Redis
- Cloudinary
- JWT Authentication
- Google Maps / Geolocation
- Docker
- GitHub Actions / CI-CD


==================================================
1. AUTHENTICATION & AUTHORIZATION
==================================================

User Roles:
- Student
- Owner
- Admin

Features:
- Register
- Login
- Logout
- JWT Access Token
- Refresh Token
- Password hashing with bcrypt
- Forgot password
- Reset password
- OTP verification

Authorization:
- Role-based access control
- Students can search and review
- Owners can create and manage their own listings
- Admins can verify and manage listings

==================================================
3. SEARCH & FILTERING
==================================================

Students should be able to search by:

- Location
- Hostel/PG name
- Rent range
- Hostel or PG
- Allowed gender
- Facilities
- Room type
- Availability
- Rating

Example:

"Find female PGs under $300 within 5 km of LD College."


==================================================
4. GEOLOCATION & GEO-SPATIAL SEARCH
==================================================

Implement MongoDB 2dsphere index.

Features:

- Store latitude and longitude
- Search hostels near a location
- Find hostels within a specific radius
- Sort hostels by distance

Example:

"Find all PGs within 5 km of my current location."

Important concepts:

- GeoJSON
- 2dsphere index
- $near
- $geoWithin


==================================================
5. IMAGE MANAGEMENT
==================================================

Use Cloudinary.

Features:

- Upload multiple hostel images
- Store Cloudinary URL
- Store publicId
- Delete individual images
- Delete images when hostel is deleted
- Replace hostel images

Database:

photos[]
    - url
    - publicId


==================================================
6. REVIEWS & RATINGS
==================================================

Create a separate Review collection.

Review:

- user
- hostel
- rating
- comment
- createdAt

Features:

- Add review
- Update review
- Delete own review
- One review per user per hostel
- Calculate average rating
- Calculate total review count

Database index:

Unique compound index:

(user, hostel)


==================================================
7. ADMIN VERIFICATION
==================================================

Owner creates a hostel.

Initial state:

isVerified = false

Admin can:

- View pending listings
- Approve listing
- Reject listing
- Remove listing
- Block owner

Only verified hostels should appear in public search.


==================================================
8. PAGINATION
==================================================

Implement pagination for hostel listings.

Basic:

- page
- limit

For large-scale systems:

- Cursor-based pagination

Example:

GET /api/v1/hostels?cursor=xxx&limit=20


==================================================
9. REDIS
==================================================

Use Redis for:

- OTP storage
- Caching popular searches
- Caching hostel details
- Rate limiting
- Temporary data

Example:

Student searches:

"PGs near LD College"

Cache the result temporarily.

If another user makes the same search:

Redis returns cached data instead of querying MongoDB.

11. API DESIGN
==================================================

GET    /api/v1/hostels/:id/reviews
PATCH  /api/v1/reviews/:id

Admin:

GET   /api/v1/admin/hostels/pending
PATCH /api/v1/admin/hostels/:id/verify
PATCH /api/v1/admin/hostels/:id/reject
